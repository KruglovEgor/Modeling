# Отчет по лабораторной работе №7
## Классификация математических задач с использованием Transformer моделей

## 1. Цель работы

Изучение методов fine-tuning предобученных Transformer моделей для задачи многоклассовой классификации текстов. Сравнение различных подходов к обучению (с заморозкой и без заморозки backbone) и анализ механизма attention.

## 2. Задачи

1. Реализовать архитектуру классификатора на основе Transformer из HuggingFace
2. Разработать функцию управления обучаемостью слоев (freeze/unfreeze backbone)
3. Создать универсальную функцию обучения с поддержкой обоих режимов
4. Обучить модель RuBERT-tiny2 в двух режимах
5. Обучить модель MathBERT в двух режимах
6. Реализовать визуализацию attention maps
7. Проанализировать изменения attention до и после обучения
8. Сравнить результаты всех моделей

## 4. Реализация

### 4.1. Класс TransformerClassificationModel

Разработан модульный класс для классификации на основе любой модели из HuggingFace:

**Архитектура:**
- **Backbone:** Предобученный трансформер (RuBERT-tiny2 или MathBERT)
- **Pooling:** Извлечение [CLS] токена
- **Dropout:** Регуляризация (p=0.3)
- **Classifier:** Полносвязный слой (hidden_size → num_classes)

**Особенности:**
- Поддержка возврата attention weights для визуализации
- Автоматический расчет loss при наличии меток
- Гибкая конфигурация через AutoConfig

### 4.2. Функция freeze_backbone

Реализует управление обучаемостью параметров:

**Frozen режим:**
- Backbone замораживается (requires_grad=False)
- Обучается только classifier head
- Параметры: ~1-2% от общего числа
- Время обучения: быстрое
- Применение: feature extraction, малые датасеты

**Unfrozen режим:**
- Все параметры обучаемы
- Полная адаптация модели к задаче
- Параметры: 100%
- Время обучения: медленное
- Применение: достаточно данных, domain adaptation

### 4.3. Функция train_transformer

Универсальная функция обучения с поддержкой:
- Выбора режима заморозки
- AdamW оптимизатора
- Linear warmup scheduler
- Gradient clipping (max_norm=1.0)
- Early stopping по validation accuracy
- Отслеживания метрик (loss, accuracy, F1-score)

**Гиперпараметры:**
- **Frozen:** lr=2e-3, warmup=50 шагов, epochs=5
- **Unfrozen:** lr=2e-5, warmup=100 шагов, epochs=5
- **Batch size:** 16
- **Max gradient norm:** 1.0

## 5. Эксперименты

### 5.1. RuBERT-tiny2

**Модель:** cointegrated/rubert-tiny2  
**Параметры:** 29M  
**Hidden size:** 312  
**Предобучение:** Русскоязычные тексты (общая лексика)

#### Результаты:

| Режим | Val Accuracy | Обучаемых параметров | Время эпохи |
|-------|--------------|---------------------|-------------|
| Frozen | 59.42% | ~2% | ~5 сек |
| Unfrozen | **60.94%** | 100% | ~18 сек |

**Наблюдения:**
- Небольшая разница между frozen и unfrozen (~1.5%)
- Unfrozen режим дает прирост качества
- Модель не специализирована под математику, но показывает отличные результаты

### 5.2. MathBERT

**Модель:** tbs17/MathBERT  
**Параметры:** 110M  
**Hidden size:** 768  
**Предобучение:** Математические тексты, формулы, символы

#### Результаты:

| Режим | Val Accuracy | Обучаемых параметров | Время эпохи |
|-------|--------------|---------------------|-------------|
| Frozen | 57.52% | ~0.6% | ~12 сек |
| Unfrozen | 60.81% | 100% | ~45 сек |

**Наблюдения:**
- Unfrozen режим дал значительный прирост (+3.3%)
- Предобучение на математике дает преимущество
- Результаты очень близки к RuBERT-tiny2 (60.94%)

## 6. Сравнительный анализ

### 6.1. Итоговая таблица

| Модель | Val Accuracy | Test Accuracy | Test F1-Score |
|--------|--------------|---------------|---------------|
| **RuBERT-tiny2 (Unfrozen)** | **60.94%** | **59.29%** | **53.57%** |
| MathBERT (Unfrozen) | 60.81% | - | - |
| RuBERT-tiny2 (Frozen) | 59.42% | - | - |
| MathBERT (Frozen) | 57.52% | - | - |

### 6.2. Ключевые выводы

**Влияние заморозки backbone:**
- Для обеих моделей: Unfrozen режим дает прирост качества
- Для RuBERT: разница 1.5% (59.42% → 60.94%)
- Для MathBERT: разница 3.3% (57.52% → 60.81%)
- Frozen режим оправдан только при жестких ограничениях по времени

**Сравнение моделей:**
- RuBERT-tiny2 (60.94%) и MathBERT (60.81%) показали практически идентичные результаты
- Domain-specific предобучение не дало значительного преимущества (всего 0.13% разница)
- Компактная модель (RuBERT, 29M) успешно конкурирует с большой (MathBERT, 110M)
- Для данного датасета понимание русского языка оказалось важнее математической специализации

**Производительность:**
- Test accuracy (59.29%) близка к validation (60.94%) — нет переобучения
- F1-score (53.57%) ниже accuracy из-за дисбаланса классов
- Сильные классы: geometry (F1=0.92), number_theory (F1=0.73), polynoms (F1=0.65)
- Слабые классы: dirichlet (F1=0.08), graphs (F1=0.03), invariant (F1=0.00)

## 7. Анализ Attention Maps

### 7.1. Визуализация

Реализована функция `draw_first_layer_attention_maps()` для визуализации attention patterns первого слоя трансформера.

**Анализируемые параметры:**
- Attention heads: 0, 1, 2
- Слой: первый (low-level features)
- Режимы: до обучения vs после обучения

### 7.2. Наблюдения до обучения

**RuBERT-tiny2:**
- Общие синтаксические паттерны
- Внимание к служебным словам
- Универсальные языковые зависимости

**MathBERT:**
- Фокус на математических терминах
- Внимание к числам и операторам
- Уже специализирован под математику

### 7.3. Изменения после обучения

**Frozen режим (RuBERT, MathBERT):**
- Attention patterns **НЕ изменились**
- Backbone остался неизменным
- Адаптировался только classifier head
- Карты идентичны предобученным

**Unfrozen режим (RuBERT, MathBERT):**
- Attention patterns **изменились**
- Фокус на ключевых словах темы
- Усиление внимания к определяющим терминам
- Адаптация под задачу классификации

**Ключевое наблюдение:**
- Unfrozen режим позволяет модели перенастроить attention механизм
- Модель "учится" обращать внимание на слова, важные для определения темы
- Frozen режим сохраняет исходные паттерны, полагаясь только на classifier

## 8. Проблемы и решения

### 8.1. Дисбаланс классов

**Проблема:** Неравномерное распределение

**Решения:**
- Использован stratified split
- Weighted F1-score для оценки
- Conditional stratify (отключается при малых классах)

### 8.2. Малые классы

**Проблема:** Классы dirichlet, graphs, invariant показывают низкие метрики

**Причины:**
- Недостаточно примеров для обучения
- Сложность задачи (специфические темы)
- Возможное пересечение с другими классами

**Возможные улучшения:**
- Аугментация данных (перефразирование)
- Focal Loss для борьбы с дисбалансом
- Увеличение датасета

### 8.3. Ограничения GPU

**Решение:**
- Batch size = 16 (оптимально для 10GB VRAM)
- Gradient accumulation не требуется
- Mixed precision training может ускорить

## 9. Выводы

1. **Важность понимания языка:** RuBERT-tiny2 и MathBERT показали практически идентичные результаты (60.94% vs 60.81%), что свидетельствует о том, что для данного датасета на русском языке понимание языка важнее математической специализации.

2. **Unfrozen fine-tuning эффективнее:** Полное дообучение дает значительный прирост для обеих моделей (+1.5% для RuBERT, +3.3% для MathBERT), позволяя адаптировать весь механизм внимания под задачу.

3. **Frozen режим имеет ограниченную применимость:** Оправдан только при жестких ограничениях по времени/памяти или очень малых датасетах.

4. **Attention механизм адаптируется:** Unfrozen обучение позволяет модели изменить attention patterns под конкретную задачу, улавливая важные для классификации признаки.

5. **Качество зависит от данных:** Дисбаланс классов и малое количество примеров в некоторых категориях ограничивают итоговое качество.

## 10. Рекомендации по улучшению

1. **Увеличение датасета:** Собрать больше примеров для малых классов
2. **Data augmentation:** Применить перефразирование/back-translation
3. **Ensemble методы:** Комбинировать предсказания нескольких моделей
4. **Focal Loss:** Борьба с дисбалансом классов
5. **Longer training:** Увеличить количество эпох с ранней остановкой
6. **Hyperparameter tuning:** Оптимизация learning rate, dropout, batch size
